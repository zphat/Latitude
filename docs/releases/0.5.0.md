# Latitude 0.5.0 — formats and separate audio

Download **Latitude-0.5.0-Windows-x64-Setup.exe**, close any running Latitude copy, and run the installer. Open Latitude from your desktop or Start menu. Existing preferences and recordings are retained. The ZIP is an optional portable alternative; keep all its extracted files together.

## Choose your format and tracks

- **Keep microphone and desktop sources separate** is explicit and on by default. Video exports keep Full mix plus each recorded microphone and desktop source as named audio streams. Turn it off for a mix-only delivery without deleting originals.
- Eight output formats: **MP4, MKV, MOV, WebM, WAV, FLAC, MP3 and M4A**. MP4, MKV and MOV are highlighted video suggestions. Each choice explains compatibility, space, audio separation and encoding cost.
- MP4 stays the easy default. MKV uses 24-bit FLAC audio; MOV uses 24-bit PCM. WebM uses VP9/Opus. Audio-only exports save the mix and each selected source as separate files.
- Settings chooses the preferred format created after recording stops. A take still records recoverable video and separate audio originals first. Export can change one take's options or remember new defaults.
- CapCut workflows retain aligned WAV editing files and optional mic-only / desktop-only video copies. Some editor versions do not expose embedded audio tracks; MP4 plus WAVs remains the practical fallback.

## Smaller exports and polish

- WAV editing copies are optional. Turning them off avoids duplicate stems/raw backups and writes the normalized mix directly into the final output without an intermediate WAV.
- H.264 picture streams copy into MP4/MKV/MOV when available. Per-source video copies reuse encoded streams. Slow VP9 conversion stays outside live recording.
- Takes shows the format, audio track/file count and delivered media size. Play opens the actual selected video or audio format, with compatibility for previous MP4 exports.
- Original recordings and earlier exports remain intact. Cancellation, interrupted recovery, measured loudness/true peak and separate-source routing remain covered by tests. Audio-only recovery works even when the video file is unavailable.

## Verification and next milestone

46 automated tests pass on the development host, including real encoding/decoding of all eight formats, isolated-tone routing, mix-only outputs, sample equivalence for lossless audio, 44.1/48 kHz handling, editor copies and playback. Browser checks cover the recording pipeline, crops, scene controls, idle suspension, saved format preferences and compact layouts. The Windows publication gate additionally runs the format suite against the bundled encoder, verifies the package, installs it, opens the actual renderer from another directory, checks shortcuts and uninstalls while retaining user data.

In a 30-second synthetic export comparison, disabling WAV editing copies reduced delivered media from 40.5 MB to 3.1 MB while retaining all four embedded audio tracks. Export time was similar. This is an export-storage example, not a whole-app CPU or OBS comparison; real savings depend on the recording.

The next milestone is Linux capture/audio integration, starting with Fedora KDE/Wayland and Ubuntu validation. Shared feature development does not need to be finished before starting that work. A Linux installer is not included in this release.

This remains an unsigned Windows x64 beta. Real-device routing, long recordings and listening quality need hardware feedback.
